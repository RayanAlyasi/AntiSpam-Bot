## 2026-10-17 · WP-G bundle (F-039, F-041–F-045, F-048, F-049, F-102, F-113, F-123, F-127) · §6, §7.2–§7.5, §9.8, §12.3, §14

- **Hard keyword, phrase and regex rules are policy violations (`Hard`), not known spam (§7.1 vs §7.3).** §7.1 lists keyword and regex blocklists among the T0 CERTAIN checks, but §7.3's list of `known` evidence names only exact targets (domains, URLs, numbers, channels, invites, hashes). The conservative reading was taken: a hard text rule deletes silently and never bans. Hard exact rules and spam fingerprints are `Known`.
- **Fuzzy matches are always weighted**, even for a hard rule, and only phrases of 6 or more characters are fuzzy-matched (one edit at 5 characters turns `loans` into `loan`).
- **Precedence of lists (§6 step 4, F-048).** Scopes are walked narrowest first (group, bot, global). An allow decides, and so does a hard deny or, for exact values, a spam fingerprint: a group allow overrides a global deny and a group hard deny overrides a global allow. A weighted rule never hides stronger evidence; it is kept and the walk goes on, so a wider hard rule, fingerprint or allow still decides. Per link, domain → URL prefix → url fingerprint, and a weighted hit doesn't stop that chain. Within one scope the most specific domain / longest prefix counts and allow beats deny. Group settings' `allowlist.domains` and `content.link_domains.allow` are allowed before any rule. `content.link_domains.block` is left to the content policy (§9.3): it's a "content" rule, so it's rule-breaking, not known spam.
- **Scopes are `global`/`bot`/`group`** as in §14 (§12.3 says "account" for bot). Global rules in a pack apply only to groups whose settings subscribe to it; global rules without a pack apply everywhere.
- **`fingerprints` primary key is `(kind, value, scope, scope_id)`** (§14 has `(kind, value, scope)`): a group-scoped fingerprint needs its group. Re-labelling (spam → allow on an overturn) updates the row.
- **Keyed number hashes are lower-case hex text** (`redact.PhoneHash`) in `number_blacklist.pn_hash`, number rules and `number` fingerprints; `corpus_entries.number_hashes` stays `bytea[]` as in §14 (the decoded bytes).
- **Corpus normalized text is computed from the redacted text**, so masked third-party numbers, emails and names aren't kept in another form. SimHash/MinHash are therefore over the redacted text too; F-117 must fingerprint incoming messages the same way only if it compares against `text_norm` directly (the stored fingerprints are what it should use).
- **WhatsApp-native links don't add `whatsapp.com`/`wa.me` to an entry's domains**: learning that domain would block every invite. Their targets (invite codes, channels, numbers) are kept.
- **Person columns have no foreign key yet** (`created_by`, `person_id`, `added_by_person`, `removed_by_person`, `decided_by_person`, `admin_person_id`): `app.persons` comes from wp-f, not merged when this landed. Follow-up: add `REFERENCES app.persons(id)` in a later migration so identity merges re-point them.
- **Reload backstop.** Besides NOTIFY, the holder reloads every 5 minutes and after each LISTEN reconnect (notifications sent while disconnected are lost). Hit counters (`hits`, `last_seen`) don't fire the trigger.
- **Migrations are 00030–00032**, the range reserved for wp-g in the shared notes (00030–00049). For a while wp-c's `TestMigrateFreshDatabase` required gap-free versions and these were 00004–00006; #21 changed it to count migrations, and staging has since taken 00004–00008 itself.
- **Analyzers are generic over the policy type `P`** and read group settings through `ruleview.Settings`, because `detect.Analyzer.Analyze` doesn't receive the policy. Registering them in the pipeline is wp-l's (F-088).
- **Bounded scans for the tier budgets (§7.1).** Regex rules scan the first 4 KiB of each prepared surface and fuzzy matching the first 200 words; keyword (Aho-Corasick), link and number checks see the whole text. A padded message could hide a regex-only pattern past 4 KiB; the alternative was hard regex verdicts being dropped when T0 overran its budget.
- **The confusables skeleton is matched only when Norm has a non-ASCII letter.** TR39 maps Latin-to-Latin look-alikes too (m→rn, 1→l), so on plain ASCII text it only produced false matches (`corn` in ".com"). Cross-script look-alikes always involve a non-ASCII letter.
- **Corpus URLs are redacted, and phone-target links (wa.me, api.whatsapp.com/send) aren't stored**; their numbers are kept as keyed hashes only.
