## 2026-10-17 · F-013 · §4, §5.1

- **The connector lives in `internal/wa/adapter/connector`.** Only `internal/wa` may import whatsmeow, and the arch map's `wa-adapter` component covers `internal/wa/adapter/**`. The connector reaches the store, inbox and identity only through interfaces (`Lease`, `Registry`, `wa.EventSink`) wired by main.
- **Event types are in `internal/wa` (new file `events.go`)**, so every package can consume them without whatsmeow.
- **Only message events are handled synchronously.** §5.1 has group events update state from the handler, but database writes or IQ lookups on the receive loop can block or deadlock it (IQ answers arrive on that loop). Non-message events go through per-bot queues instead: connection and account events (bans, logouts, replaced streams) on a priority queue that never drops, group and profile events on a bounded queue. If that one overflows, an event is dropped and logged, and the 6-hourly group refresh repairs the state.
- **The decrypted-event buffer is on** (`EnableDecryptedEventBuffer`), so a message left unacked after a failed inbox insert is really redelivered (whatsmeow would otherwise drop the redelivery with ErrOldCounter).
- **The manager reports its own disconnects** (whatsmeow emits nothing for a requested `Disconnect`): `Disconnected` when the bot is down as far as it knows, and a new `Released` state when this process just stopped owning the bot (shutdown, lease taken over, logout), which health tracking doesn't alert on.
- **StreamReplaced backs off for 5 minutes** before the manager tries that bot again (DESIGN.md doesn't say), so two processes can't kick each other off in a loop.
- **A message that can't be converted stays unacked** (WhatsApp redelivers it) rather than being acked and lost.
