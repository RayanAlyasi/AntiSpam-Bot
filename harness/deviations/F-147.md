# F-147 to F-150: conservative readings of DESIGN.md §7.8

- **Recall is measured before writing.** §7.8 says the hold-out is evaluated after storing. The
  replay runs against the live corpus plus the batch's entries added in memory, before the
  transaction, so a dry run reports the same numbers and `--allow-ham` fingerprints can't hide
  the ham false-positive check. The result is the same as replaying after the write.
- **Recall uses an established member as the sender**, one per message, two hours apart, so the
  new-member signal, flood limits and safety rails can't inflate it. It's a lower bound.
- **AI isn't called** in the replay; an uncertain message counts as sent to admins.
- **Language detection** is a script guess (ar, en, ru, und), only used for the report.
- **`--allow-ham` needs a group scope:** allow-lists are per group.
- **`--holdout-clusters FILE`** is an addition: it lets the operator reuse a hold-out list chosen
  outside the bot. It replaces the random split rather than adding to it, so the hold-out is
  exactly what the operator chose.
- **The hold-out share counts clusters** (the contract's "~Holdout share of clusters"), spread
  over category×kind strata by largest remainder, each capped at ceil(share × its clusters).
- **Clusters:** a record without `cluster_id` is linked to every record it loosely matches; if
  that links two named clusters, they become one split unit (named ids are never split apart).
- **Numbers are found with no default region**, the same as the live fast lane
  (`pipeline.NormalizeTexts`), so stored and live texts compare like for like. Local numbers
  written without a country code are masked as a bare `[phone]` and can't be matched by hash.
- **The command applies pending migrations** like `serve`, so it refuses a database migrated by a
  newer release.
- **Records are imported as `active` entries** (CERTAIN evidence for tight near-duplicates), as
  §7.8 says: "Exact and tight near-duplicate matches count as known evidence".
