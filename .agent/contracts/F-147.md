# F-147: dataset import (covers F-147, F-148, F-149, F-150)

**Goal:** `antispam corpus import <file|-> --scope instance|group:<jid> [--holdout 0.2] [--holdout-clusters FILE] [--allow-ham] [--dry-run]`
turns a labeled spam dataset into redacted, fingerprinted corpus entries plus a cluster-split hold-out, and
`antispam corpus remove --import <id>` undoes it. Ham is never stored as text.

**Behaviour**
- Parse JSONL or CSV-with-header (sniffed from content: first non-blank char `{` means JSONL), from a file or stdin. Fields per §7.8. `Line` is the file's own 1-based line (blank lines count; CSV header is line 1). Blank JSONL lines are skipped. A UTF-8 BOM, CRLF, any column order and a subset of columns are fine. Text is returned unchanged (normalization happens at import).
- `label` empty → `spam`; only `spam`/`ham` valid. `media_sha256` is a string or array (JSONL), 64 hex chars each. CSV list cells (`urls`, `media_sha256`) are whitespace-separated.
- Rejected, with line and non-empty reason, never a whole-file error: malformed JSON, non-string `text`, missing or blank text without `media_sha256`/`phash`, unknown label, bad sha256, wrong CSV field count. Parse must never panic.
- Each spam record goes through the bot's own path (`textnorm.Prepare` + `corpus.FromMessage`, HASH_KEY): stored text redacted, numbers only as keyed hashes, SimHash/MinHash set. Entries: `source=import`, `status=active`, `label=spam`, `kind=message`, `import_batch_id`; scope `global` (NULL group) for instance, `group`+JID otherwise. One `import_batches` row (file_name, scope `instance|group`, group_jid).
- Dedupe exact (after normalization, so zero-width/fullwidth variants are exact) and tight near-duplicates (neardup Certain): in-file → `MergedInFile`; against the live corpus **in the same scope** → `MergedExisting`. Merged records are not stored and not held out. Re-importing a file stores nothing new.
- Accounting: `Read = len(recs)+len(rejected)`; `Spam = Imported + Holdout + MergedInFile + MergedExisting`; `Imported` = corpus entries, `Holdout` = eval_corpus rows written; `Rejected` echoes the input.
- Split by cluster, stratified by category and kind, ~`Holdout` share of clusters (0 = none). `cluster_id` is authoritative when given; otherwise near-duplicates (loose band included) form one cluster. `HoldoutClusters` ids always go to the hold-out. No cluster on both sides. Hold-out rows: `eval_corpus` source `import_holdout`, label spam, batch id, one `cluster_key` per cluster, redacted `text_norm`, category, kind, language. A record duplicating an existing hold-out row is never stored as a corpus entry.
- Recall: hold-out runs in memory through the real pipeline (AI off unless configured): `Total = Deleted + ToAdmins + Missed`. Nothing is sent and no detections/actions rows are written.
- Ham: in memory only. `HamCaught` = ham the pipeline would delete or send to admins. With `AllowHam` (group scope) ham adds `corpus_allow` fingerprints tagged with the batch. Ham text never reaches any table.
- `Thin` names each category and language with < 10 spam examples. `DryRun`: same counts, `BatchID 0`, zero rows written anywhere.
- `Remove`: deletes the batch's corpus entries, eval rows, allow rows and rules/fingerprints learned only from it; other batches untouched; batch row kept, marked removed. Second call → zero `Removed`, nil. Unknown id → error.

**Public surface:** `internal/corpusimport`: `Record`, `Rejection`, `Parse`, `Scope`, `ParseScope`, `Options`, `Recall`, `Report` (fields as in the stub). `internal/corpusimport/pgimport`: `Run`, `Remove`, `Removed{Entries, Holdout, Allow}`. Tests read §14 tables `corpus_entries`, `import_batches`, `eval_corpus`, `corpus_allow`, `rules`, `fingerprints`.

**Out of scope:** per-band/per-type recall breakdown and CI gate (F-151), language detection quality, media decoding, the CLI flag parsing itself, docs/CORPUS_FORMAT.md content (F-147 builder writes it; untested).

**DESIGN.md refs:** §7.2, §7.5, §7.8, §14 (import_batches, eval_corpus), §17, §18.

**Assumptions (conservative readings):** non-string JSON `text` is rejected (a number would lose digits); `Options.Holdout` is taken literally, the 0.2 default lives in the CLI flag; near-duplicate clustering without `cluster_id` links at the loose band so no near-duplicate leaks into the hold-out; hold-out text is redacted like corpus text; dedupe also covers existing hold-out rows; `AllowHam` with instance scope is an error before any write (untested); same text in another scope is stored again.

**Acceptance tests** (`acceptance/corpusimport/`; `*_integration_test.go` use tag `integration`)
- TestParseJSONL: all fields read, label defaults to spam, media_sha256 string or array, blank lines skipped.
- TestParseJSONLRejectsWithLineNumbers: each invalid JSONL line rejected with its line and a reason.
- TestParseLineNumbersCountBlankLines: line numbers are the file's physical lines.
- TestParseCSV: quoted commas/quotes, whitespace-separated URLs, media-only row, header is line 1.
- TestParseCSVHeaderSubsetAndBOM: BOM, CRLF, subset and reordered columns.
- TestParseCSVRejectsWithLineNumbers: empty text, bad label, wrong field count, bad sha256.
- TestParseKeepsUnicodeText: Arabic, emoji, zero-width and fullwidth text unchanged.
- TestParseScope: instance and group JIDs accepted; lid, PN, empty and unknown scopes rejected.
- FuzzParse: no panic; labels valid; lines in range and increasing; no record without text or media.
- TestImportStoresEntriesInScope: batch row, entry source/status/label/scope, fingerprints, report counts.
- TestImportRedactsAndHashesNumbers: no raw number or email anywhere; entry keeps a number hash.
- TestDryRunWritesNothing: every table unchanged; dry-run counts equal a real run's.
- TestDedupeCounts: obfuscated and one-word-edit copies merged in file; edit of existing merged.
- TestDedupeOnlyWithinScope: other scopes store again; re-import merges everything.
- TestThinCategoriesAndLanguages: thin category and language named, well-covered not.
- TestHoldoutKeepsClustersTogether: no cluster_id on both sides; eval rows and counts consistent.
- TestHoldoutComputedClusters: without cluster_id, near-duplicate variants stay on one side.
- TestHoldoutRatio: 0, 0.2, 0.5 roughly honoured.
- TestHoldoutStratified: each category and kind represented, small stratum not over-sampled.
- TestHoldoutForcedClusters: listed clusters only in the hold-out.
- TestReimportNeverLeaksHoldout: re-import never turns hold-out into corpus entries.
- TestHoldoutRecall: loose rewrite caught, unrelated missed, totals add up, nothing recorded.
- TestHamNeverStored: ham text in no table; allow-list rows only with AllowHam.
- TestHamFalsePositiveCount: only the ham near-duplicate of spam counts as caught.
- TestRemoveUndoesBatch: tables back to pre-import counts, earlier batch intact, idempotent, unknown id errors.
