# F-088 deviations

- **§4.1 one transaction:** the detection, the local ban, the queued delete/kick and the review
  item with its queued post commit together. The review store and queue join the transaction
  through the context (`pipeline/pgstore.Conn`, `TxFrom`), because wp-k's review service is a
  long-lived object.
- **Redelivery guard:** besides the inbox's own dedupe, the fast lane takes an advisory lock on
  (group, message) and skips a message that already has a detection. The envelope carries no
  edit sequence, so an edit of a message that already has a detection isn't analysed again. An
  edit of a clean message is. Conservative: no second action on one message ID.
- **No person record → no automatic ban:** when the sender can't be resolved to a person
  (identity not seen yet), the spam is still deleted and the ban goes to admins as a review.
- **Protected groups** come from wp-f's groups table (status active: the bot is an admin), the
  rule the inbox router uses. The chat handler's `.groups`/`.use` also list groups still waiting
  for admin rights, so an admin can switch one to shadow mode by DM before promoting the bot
  (README).
- **Numbers without a country code** aren't read from text (region ""): v0.1 group settings have
  no default-country key yet. vCard waids and international numbers are read.
- **AI context bundle (F-108) off:** v0.1 group settings have no `ai.context` key, so the AI sees
  only the message (the private choice).
- **`HASH_KEY` (new):** DESIGN names no variable for the keyed number hashes. It's required, and
  the bot refuses to start without it once a number is paired. A fresh install with no paired
  number only logs an error, because the committed F-008 serve tests start the binary with no
  `HASH_KEY`. No key is ever generated.
- **Corpus learning adapter (F-114 side):** `fastlane.CorpusLearning` implements `review.Corpus` on
  wp-g's corpus store: confirm → active group entry; overturn → retract plus a text-free
  fingerprint allow-list entry. Migration 00034 adds `app.corpus_messages` (message → entry) and
  `app.corpus_allow`.
- **Wired beyond the contract's scope:** the chat handler (commands, DMs, review votes),
  review timeouts and the evidence purge. The running bot needs them for the README's shadow
  test. The handler's blacklist, lists, history, stats and join-by-link ports stay nil (their
  commands reply "not available") until their Postgres adapters exist.
- **Database pool floor:** the binary sets `pool_max_conns=20` unless DATABASE_URL already sets
  it. A review opened inside a message's transaction looks the group up on a second pooled
  connection, and pgxpool's default (max(4, CPUs)) could deadlock under load.
- **Known minor gaps:**
  - A review short-code collision inside the message transaction aborts it, and the inbox retries
    the message.
  - The rule-view settings read uses a background context (ruleview.Settings has none).
  - Without HASH_KEY and before any pairing, a number paired later connects while messages go
    unmoderated until a restart. Compose requires HASH_KEY, which prevents this in the
    documented setup.
- **Trust restore on overturn** (`review.Standing`) is a no-op until a trust store exists.
