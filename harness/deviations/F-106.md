## 2026-10-17 · F-106/F-107 · §7.4 (adapters)

- **Provider seam below `ai.AIClassifier`.** The adapters implement a raw completion interface (`internal/ai/llm.Completer`: system prompt + data block in, text + usage out) instead of `AIClassifier` directly. Prompt rendering, strict parsing and the one retry (F-104/F-105, wp-e) sit above it, so each adapter stays a thin transport and nothing outside the adapter packages sees a provider type. The `AIClassifier` built on top comes in the follow-up PR, once wp-e's `internal/ai` lands.
- **Anthropic uses the official `anthropic-sdk-go`**, created with `WithoutEnvironmentDefaults` (it never reads `ANTHROPIC_*` variables: the key comes only from `ai.api_key_env`), `WithMaxRetries(0)` and OpenTelemetry off. Effort is sent only when configured, because older models reject it.
- **Anthropic default max tokens is 4,096.** Current Claude models think adaptively and that thinking counts against `max_tokens`; a small cap would truncate most answers into "unsure". A truncated answer maps to `ErrTruncated` (→ unsure).
- **OpenAI-compatible sends `max_tokens`**, not `max_completion_tokens`: every local server named in §7.4 accepts it. Some newer hosted reasoning models only accept the latter; deployers can switch to a compatible model. Noted as a follow-up.
- **No adapter retries.** One `Complete` makes one HTTP call (the `auto` JSON-mode resend after a 400/422 schema rejection is the only exception), so the 5 s deadline holds and retry policy stays in one place.

## 2026-10-17 · F-109 · §7.4, §14, §16 (budgets and metrics)

- **The 80% alert needs no extra state.** Reservations are atomic and count one call each, so exactly one reservation per window crosses 80%; that caller alerts. A restart can't alert twice, and `ai_usage` keeps its §14 columns.
- **Per-group cost is in `ai_usage`, not in Prometheus labels**, to keep metric cardinality bounded; Prometheus has cost by provider and model.
- **Calls per 1,000 messages is two counters** (`antispam_ai_calls_total` ÷ `antispam_ai_messages_seen_total`), the usual Prometheus pattern, rather than a precomputed ratio.
- **Token prices are configuration, default zero** (cost 0, e.g. local models, whose cost shows as latency). §7.4 mentions "compute time" for local models: that's the latency histogram.

## 2026-10-17 · F-110 · §7.4, §11 (cache)

- **The cache key includes the context hash** (§7.4); §11's table leaves it out. Including it never reuses a verdict across different context (contract assumption 1).
- **Only spam/not_spam verdicts are cached or reused**; unsure, invalid output and errors are retried next time.
- **Cluster reuse is in memory for 24 h** (bounded to 50,000 clusters). §7.4 gives no duration; a campaign typically runs for hours, and the 30-day key cache still covers exact repeats after that.
- **408 and 504 map to `ErrTimeout`**, not to "other 4xx → invalid request" and "5xx → unavailable" as the contract's list reads. Both are timeouts reported by the server or a gateway; either way the item goes to admins and nothing is deleted, so only the metric label differs.

## 2026-10-17 · F-111/F-112 · §7.0, §7.4, §9.2 (PR 2)

- **The early-AI safety rule lives in `internal/ai/safety`, not `internal/policy`.** Work packages may not edit each other's files, and wp-i's matrix accepts `ai` in `require_source` without a track-record check. `safety.Decide` wraps `policy.Decide`; the pipeline must call it.
- **One AI confidence threshold for both labels.** `scoring.Resolve` (wp-e) uses `Thresholds.AIConfidence` for spam and not_spam; §7.0 gives 0.9 for both, so `ai.not_spam_confidence` has no separate effect yet.
- **`ai.provider: google` refuses to start**: wp-e's config accepts it, but no adapter exists in v0.1 (§7.4 says "possibly").
- **Anthropic ignores a small `ai.max_output_tokens`.** wp-e's default (256) suits non-thinking models; Claude thinks adaptively and that counts against `max_tokens`, so the adapter keeps 4,096 unless the operator sets more.
- **Schema value constraints are not sent to providers** (`llm.PortableSchema`): Anthropic rejects numeric, length and array constraints. Every answer is still validated against the full schema by `ai.ParseVerdict`.
- **The cached reason was capped, not redacted again** (PR 2). Resolved in PR 3: `gateway.Sanitize` now runs the shared redaction helper on a spam verdict's reason before it is cached or reused.
- **A cluster's shared call uses the budget of the group whose copy started it.** If that group is out of budget, the copies waiting on it go to admins too (reason budget), even from groups with budget left. This fails safe; letting such a copy retry under its own budget is a follow-up.
- **An ai-only matrix cell becomes its else action** (ask when unset) while the track record is unmet, so known evidence keeps the outcome the group configured; it never turns into `auto_ban [known]`.
- **A shared cache call stops when its last waiting caller gives up** (and at a 5-minute flight timeout), so a hung provider or store never leaks a goroutine once nobody needs the answer.

## 2026-10-17 · F-108/F-109/F-110 · §7.4, §11, §14, §17 (PR 3)

- **The context bundle reads an in-memory buffer, not the 72 h inbox.** The inbox worker (F-015, wp-f) isn't built yet, and the inbox stores raw protos, not normalized text. `aicontext.Buffer` keeps the last 100 messages per group for at most an hour, in memory only: less than the inbox keeps, and nothing is written for the AI. `aicontext.Source` lets an inbox reader replace it.
- **Replies are part of the context hash.** A message re-checked after someone replied gets a new cache key and may cost a second AI call; the reply ("scam!") is real new evidence, so the verdict isn't reused across it. The pipeline should build the context once per message (wp-l follow-up).
- **The AI migration takes the next free version, `00007_ai.sql`.** wp-c's store tests require goose versions without gaps, so a distant number isn't possible; versions 00004–00006 went to wp-i (#27) first. Any package merging after this one renumbers past 00007.
- **Expired `ai_cache` rows are purged every 6 h** by a River periodic job (`aistore.RegisterPurge`); lookups ignore rows older than 30 days in any case.
- **The replied-to message outlives older "previous" messages under the cap.** The contract says oldest first; the bundle drops previous messages first, then the replied-to message, then replies, because the message being answered matters most. With the default caps the replied-to message is never dropped.
- **The stored reason is redacted without names or region.** `gateway.Sanitize` masks phone numbers, emails and mentions; names are already masked in what is sent to the AI, so a reason rarely contains one.
- **The purge uses `cache.DefaultTTL` (30 days).** If `cache.Options.TTL` is ever changed, `aistore.RegisterPurge` must change with it.
