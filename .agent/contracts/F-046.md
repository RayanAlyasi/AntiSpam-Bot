# F-046: Tolerant URL extraction

> Acceptance tests were waived by the user's fast-track decision for v0.1 work package A (this feature isn't core). The builder's table, property and fuzz tests carry the proof, and the judge checks them against this contract.

**Goal:** find every link in a text string, including defanged and obfuscated ones, and return each in a form that `net/url` can parse. Callers apply it to each surface: body, caption, preview title/description/URL, vCard fields, location URL and comment, event join link.

**Behaviour**
- `Extract(text)` returns the URLs in order of appearance, deduplicated by exact string. Each has scheme `http` or `https` (as written, otherwise `http://` is added) and a non-empty host. Path, query and fragment are kept as written (canonicalization is F-047).
- Found: `https://…`, `www.example.com`, bare domains ending in an ICANN public suffix (`example.com/path`, `t.me/x`, `wa.me/9665…`, `chat.whatsapp.com/Code`), and IDN in Unicode or punycode (`пример.рф`, `مثال.السعودية`, `xn--e1afmkfd.xn--p1ai`).
- De-obfuscated:
  - `hxxp`/`hxxps` (any case) and `http[:]//`;
  - dots written `[.]`, `(.)`, `{.}`, `[dot]` and `(dot)`;
  - spaced dots (`example . com`);
  - the fullwidth and ideographic dots `．`, `。` and `｡`;
  - fullwidth letters, and invisibles inside the URL (`exa​mple.com`).
  
  All of these give the same URL as the plain spelling.
- Trailing sentence punctuation (`. , ! ? ; : ' "`, `،`, `؟`, closing brackets) isn't part of the URL. Balanced parentheses inside the path are (`…/Foo_(bar)`). A URL directly followed by Arabic text ends at the script change.
- False positives that must not be extracted:
  - email addresses (`ali@example.com`);
  - decimals and versions (`3.14`, `v1.2.3`);
  - bare IPv4 addresses without a scheme;
  - dotted abbreviations (`e.g.`, `a.m.`);
  - vCard property names (`item1.URL:`), though the value after them is extracted;
  - file names whose extension isn't a public suffix.
  
  A spaced dot (`word . word`) counts only when the suffix is in a builder-maintained list of common TLDs (at least com, net, org, info, biz, io, co, me, ly, xyz, top, site, online, shop, link, app) or the text has a scheme or `www`. That keeps `I'm done . now` from becoming a URL.
- Never panics. Bounded output: at most 64 URLs per call, each at most 2 KiB. Linear: 256 KiB of hostile input finishes in under 3 s with `-race`. Every result `u` satisfies `Extract(u) == []string{u}`.

**Public surface:** package `internal/normalize/urls` (new): `func Extract(text string) []string`.

**Out of scope:**
- filling `Envelope.URLs` or reading envelope types (callers do that; the package depends on nothing outside `internal/normalize`);
- canonicalization, eTLD+1 and WhatsApp-native classification (F-047);
- word-form obfuscation (`example dot com`) and spaced-out schemes (`h t t p`);
- shortener expansion and reputation.

**DESIGN.md refs:** §6 URL analyzer step 1, §5.3 (`URLs`), §6.7, §6.11, §6.12.

**Assumptions**
- Extraction works on raw text and handles NFKC and invisibles itself. F-036's separator collapsing in `Norm` could join `a.b.c.com`-style hosts, so `Norm` isn't the input.
- A bare domain with an uncommon ICANN suffix in prose (`there.it`) may still be extracted. That's accepted, because such an extraction is just an unknown domain, not a spam signal.

**Proof (builder tests):** table tests for each found form, each obfuscation, trailing punctuation, and each false-positive class; fuzz (no panic, every result parses with `net/url`, has an http(s) scheme and a host, is within bounds, and is a fixed point of `Extract`).
