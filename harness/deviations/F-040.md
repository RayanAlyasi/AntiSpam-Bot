# Deviations for the F-040 bundle (F-040, F-050, F-051, F-103, F-104, F-105, F-078)

- §6 Analyzer signature: `Analyzer[E, P any]` is generic over the envelope and policy types instead
  of naming `*Envelope` and `*Policy`, because both packages are being built in parallel; production
  code instantiates it once. Behaviour is the same.
- §6 Signal: adds `Known bool` (known-spam evidence) so the band and the `known` confidence source
  come from the signals themselves (§7.0, §7.3).
- §7.1 budgets: T0/T1 deadlines are 10 ms/50 ms (about ten times the 1 ms/5 ms targets) so a busy
  machine doesn't drop fast-tier signals; the targets stay targets.
- §7.1 short-circuit on a clean score applies only after the fast lane (T0–T1); otherwise T1
  heuristics would never run after an empty T0.
- §7.3 Σ wᵢ: each signal code counts once per message (the largest |weight| wins), so two
  blocklisted links don't double the evidence. Conservative against false positives.
- §7.3 policy + spam: a hard violation with only rules-level spam evidence is CERTAIN/violation
  with source none (deleted by policy, never banned); the spam route applies only with known spam.
- §7.4 confidence outside [0, 1], NaN or an unknown label resolves to still uncertain (ask admins).
- §7.4 categories: a fixed list (`ai.Categories`) is part of the schema; an unknown category makes
  the output invalid (retried once, then unsure), like any other schema violation.
