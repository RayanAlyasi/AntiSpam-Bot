# F-091 deviations

- **§19.1 `.env.example` → `env.example`.** The harness guard treats every path starting with
  `.env` as personal data (`hooklib.SENSITIVE`), so agents can't create `.env.example`. The same
  template ships as `env.example` (`cp env.example .env`). A human can rename it once the guard
  exempts it: see `harness/proposed/guard-env-example.md`.
- **§19.1 `postgres:16` → `postgres:18-alpine`.** The integration tests and
  `docker-compose.test.yml` already run Postgres 18, so production runs the major version the
  tests cover. Data lives under `/var/lib/postgresql` as Postgres 18 images expect.
- **§19.1 optional profiles (`media`, `local-ai`, `monitoring`) are not in the compose file.**
  None of them has a v0.1 feature behind it; the README explains how to point the AI settings at
  a local OpenAI-compatible server instead.
- **§19.1 `SESSION_SECRET` and vision settings are not in `env.example`.** v0.1 reads neither
  (the website and vision AI come later); the file documents exactly what the bot reads, which a
  test enforces.
- **`HTTP_ADDR` (new, default `:8080`).** The distroless image has no shell or curl, so the
  compose healthcheck runs `antispam healthcheck`, which needs to know the listen port. DESIGN
  names no variable for it; wp-c (F-007) was asked to serve `/healthz` on it.
