## 2026-10-17 · F-106/F-107 · §7.4 (adapters)

- **Provider seam below `ai.AIClassifier`.** The adapters implement a raw completion interface (`internal/ai/llm.Completer`: system prompt + data block in, text + usage out) instead of `AIClassifier` directly. Prompt rendering, strict parsing and the one retry (F-104/F-105, wp-e) sit above it, so each adapter stays a thin transport and nothing outside the adapter packages sees a provider type. The `AIClassifier` built on top comes in the follow-up PR, once wp-e's `internal/ai` lands.
- **Anthropic uses the official `anthropic-sdk-go`**, created with `WithoutEnvironmentDefaults` (it never reads `ANTHROPIC_*` variables: the key comes only from `ai.api_key_env`), `WithMaxRetries(0)` and OpenTelemetry off. Effort is sent only when configured, because older models reject it.
- **Anthropic default max tokens is 4,096.** Current Claude models think adaptively and that thinking counts against `max_tokens`; a small cap would truncate most answers into "unsure". A truncated answer maps to `ErrTruncated` (→ unsure).
- **OpenAI-compatible sends `max_tokens`**, not `max_completion_tokens`: every local server named in §7.4 accepts it. Some newer hosted reasoning models only accept the latter; deployers can switch to a compatible model. Noted as a follow-up.
- **No adapter retries.** One `Complete` makes one HTTP call (the `auto` JSON-mode resend after a 400/422 schema rejection is the only exception), so the 5 s deadline holds and retry policy stays in one place.

## 2026-10-17 · F-109 · §7.4, §14, §16 (budgets and metrics)

- **The 80% alert needs no extra state.** Reservations are atomic and count one call each, so exactly one reservation per window crosses 80%; that caller alerts. A restart can't alert twice, and `ai_usage` keeps its §14 columns.
- **Per-group cost is in `ai_usage`, not in Prometheus labels**, to keep metric cardinality bounded; Prometheus has cost by provider and model.
- **Calls per 1,000 messages is two counters** (`antispam_ai_calls_total` ÷ `antispam_ai_messages_seen_total`), the usual Prometheus pattern, rather than a precomputed ratio.
- **Token prices are configuration, default zero** (cost 0, e.g. local models, whose cost shows as latency). §7.4 mentions "compute time" for local models: that's the latency histogram.

## 2026-10-17 · F-110 · §7.4, §11 (cache)

- **The cache key includes the context hash** (§7.4); §11's table leaves it out. Including it never reuses a verdict across different context (contract assumption 1).
- **Only spam/not_spam verdicts are cached or reused**; unsure, invalid output and errors are retried next time.
- **Cluster reuse is in memory for 24 h** (bounded to 50,000 clusters). §7.4 gives no duration; a campaign typically runs for hours, and the 30-day key cache still covers exact repeats after that.
- **408 and 504 map to `ErrTimeout`**, not to "other 4xx → invalid request" and "5xx → unavailable" as the contract's list reads. Both are timeouts reported by the server or a gateway; either way the item goes to admins and nothing is deleted, so only the metric label differs.
