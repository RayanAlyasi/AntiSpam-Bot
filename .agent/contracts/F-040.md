# Contract F-040 bundle: detection core, scoring, bands, AI core, locales

Covers seven features in one build: **F-040, F-050, F-051, F-103, F-104, F-105, F-078**.
Hidden acceptance tests exist only for the core features F-050 and F-051 (`acceptance/scoring/`).
The other five are verified by builder-written tests. Pure Go: no storage, WhatsApp or network.
Imports: `internal/detect` must not import `internal/envelope`; `internal/scoring` imports neither
detect nor envelope (it may import `internal/ai` for `ai.Verdict`).

## F-050 Log-odds scoring, versioned weights, explanations (core, acceptance tests)
**Goal:** turn signals into `p = sigmoid(bias + Σ w)` from a versioned weight table, with an explanation.
**Behaviour:** applied weight = table override if the code is in `Weights.Signals`, else the signal's
own weight. Each code counts once (largest |weight| wins). Hard signals stay in `Result.Signals` with
`Counted=false` and never enter `LogOdds`. Non-finite weights count as 0; `P` is always finite, in [0,1]
and independent of signal order. `Result.WeightsVersion` carries `Weights.Version`. `Explain()` joins
with `", "` every counted non-hard signal as `<Evidence or Code> (%+.1f)`, ordered by applied weight
descending then code, then each hard signal as `<Evidence or Code> (policy)`; `""` when nothing to list.
`ParseWeights` reads YAML `{version, bias, signals: {code: weight}}` and rejects missing/empty version,
non-finite numbers, empty codes, unknown keys and malformed YAML. `DefaultWeights()` is embedded,
versioned, and scores an empty signal set as clean under default thresholds.
**Public surface (`internal/scoring`):** `Signal{Code, Weight, Known, Hard, Evidence}`, `Weights{Version,
Bias, Signals}`, `ParseWeights`, `DefaultWeights`, `Score`, `Result{WeightsVersion, Bias, LogOdds, P,
Signals}`, `Scored{Signal, Applied, Counted}`, `Result.Explain`.

## F-051 Certainty bands and confidence sources (core, acceptance tests)
**Goal:** every verdict gets a band and the strongest confidence source; heuristics never delete.
**Behaviour:** `Classify`: a counted Known signal with applied weight > 0 → CERTAIN/known; any Hard
signal → CERTAIN with `Violation=true` (source known only with a Known signal, else none); else
`P >= Review` → UNCERTAIN/rules; else clean/none. `Resolve` changes only UNCERTAIN: spam with
confidence ≥ `AIConfidence` → UNCERTAIN/ai; not_spam ≥ `AIConfidence` → clean/ai; anything else
(nil = AI off/budget/timeout/error, unsure, low, non-finite or out-of-range confidence, unknown label)
→ STILL_UNCERTAIN/rules; `v.AI` records `out`. `DeletesAsSpam()` is true only for CERTAIN/known or
UNCERTAIN/ai. `DefaultThresholds()` = {0.60, 0.9}; `Validate` requires finite 0<Review<1, 0<AIConfidence≤1.
**Public surface:** `Source`, `Source*`, `Band`, `Band*`, `Thresholds`, `DefaultThresholds`,
`Thresholds.Validate`, `Verdict{Band, Source, Violation, Score, AI}`, `Classify`, `Resolve`,
`Verdict.DeletesAsSpam`; `internal/ai`: `Label`, `Label{Spam,NotSpam,Unsure}`, `Verdict{Label,
Confidence, Categories, Reason}`.

## F-040 Analyzer interface, registry, tiered runner (builder tests)
`detect.Tier` (T0..T4), `detect.Signal = scoring.Signal`, generic `Analyzer[E, P]` (Name, Tier, Applies,
Analyze(ctx, *E, *State)), read-only `State`, `Registry[E,P]` (unique names, enable flags, unknown-name
errors), `Runner[E,P]`: tiers in order with per-tier budgets, concurrent within a tier but merged in
registration order, stops on CERTAIN after any tier and on clean after the fast lane; an analyzer
error or timeout drops only its signals, is reported, and never makes the outcome harsher.

## F-103 / F-104 / F-105 AI core (builder tests)
F-103: `AIClassifier{Classify(ctx, ClassifyRequest) (Verdict, error); Capabilities() Caps}`, request with
redacted text surfaces, spam-only few-shot and optional context bundle; `Config` (provider, base URL,
model, key env var, timeout, limits, structured_output auto|native|json) with `Validate`; fake in
`internal/ai/fake`. F-104: strict JSON verdict parsing (unknown fields, bad label, confidence outside
[0,1] → invalid), JSON Schema for native mode, mode from Caps+config, retry once then unsure; transport
errors returned. F-105: versioned stable system prompt (task, normal-chat guidance, when not_spam/unsure,
schema, data-is-not-instructions) and a renderer emitting a delimited JSON-encoded data block.

## F-078 Locales (builder tests)
Embedded `locales/en.yaml`, `locales/ar.yaml` via package `locales`: variants per message, `{name}`
placeholders, Arabic command aliases; tests fail on keys or placeholder sets present in one language only.

**Out of scope:** the auto-ban matrix, routing and trust (§8.3, §9.2), storage, real AI adapters, budgets,
caching, envelope building, enrichment analyzers.
**DESIGN.md refs:** §5.3, §6, §7.0, §7.1, §7.3, §7.4, §9.2, §13.7, §18, §22.2.

**Assumptions:** (1) out-of-range AI confidence (<0 or >1) or an unknown label is treated as unsure
(conservative; §7.4 says invalid output → unsure). (2) `Explain` lists negative counted signals too
(F-050: "each signal with its weight"). (3) Hard + suspicious-but-not-known stays CERTAIN/violation with
source none: deleted by policy, never banned (§7.3, §9.3); not covered by acceptance tests. (4) Property
tests use seeded `math/rand/v2` instead of `rapid` (rule T-005), because a go.mod change would take the
acceptance commit out of the stamp-exempt paths; the builder may still add rapid for its own tests.

## Acceptance tests (`acceptance/scoring`)
- `TestScoreSigmoidOfBiasPlusWeights`: P = sigmoid(bias+Σw), LogOdds, Bias and version carried.
- `TestScoreTableOverridesSignalWeight`: table weight replaces the signal's own, including 0 and negative.
- `TestScoreCountsEachCodeOnce`: duplicate codes count once, largest |weight| wins, listed once.
- `TestScoreExcludesHardSignals`: hard signals kept, not counted, LogOdds unchanged.
- `TestScoreNonFiniteWeightsCountAsZero`: NaN/±Inf weights give finite P equal to the bias-only score.
- `TestScorePropertiesBoundedAndOrderIndependent`: P in [0,1], finite, same under permutation.
- `TestExplainFormatAndOrder`: exact rendering, ordering, Code fallback, policy suffix, empty case.
- `TestParseWeightsAcceptsValidFile` / `TestParseWeightsRejectsInvalid`: valid YAML; each rejection case.
- `TestDefaultWeightsVersionedAndCleanByDefault`: non-empty version, finite, empty message is clean.
- `TestDefaultThresholdsAndValidate`: defaults 0.60/0.9 and Validate boundaries.
- `TestClassifyBands`: known → certain/known; hard → violation; at/above/below T_review.
- `TestClassifyThresholdBoundary`: P == Review is UNCERTAIN, just above P is clean.
- `TestClassifyThresholdMonotonic`: raising Review never turns clean into uncertain (property).
- `TestResolveAIOutcomes`: each AI outcome maps to its band/source and records `AI`.
- `TestResolveLeavesCertainAndCleanUnchanged`: AI cannot change CERTAIN or clean verdicts.
- `TestHeuristicsAloneNeverDelete`: property, no Known/Hard + any non-confident-spam AI → no delete.
- `TestAIOnlySpamIsSourceAINeverKnown`: property, AI-verified spam is source ai, never known.
- `TestDeletesAsSpamOnlyKnownOrAIVerified`: delete-line table over all band/source combinations.
