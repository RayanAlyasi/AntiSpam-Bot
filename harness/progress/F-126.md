## 2026-10-18 · F-126 · Blacklist hooks wired (WP-K, sixth PR)

- Built: `cmd/antispam/grouphooks.go` calls the three hooks in production. Group events are queued after the tracker stores them, and one goroutine handles them in order, so no hook runs on whatsmeow's receive loop.
  - Joins in groups the bot acts in (bot is admin, mode enforce) go to `OnJoin`, matched through the event's LID↔PN pairs and skipping the bot itself. Then they go to `policy.Bans.OnJoin` for local bans' rejoin block (F-077, wp-i's): a rejoin by link is kicked at P0, and a re-add by a current admin lifts the block. Shadow and paused groups are left alone.
  - The group's own rejoin block always applies to listed people too, and an admin's re-add doesn't lift it for them: the list wins (see deviations).
  - Join requests in approval-mode groups are polled every 5 minutes, one paced read every 2 s, and go to `OnJoinRequests`.
  - `blacklistSink` sits in front of the fast lane and calls `OnMessage` for every group message (edits and revokes are skipped). A listed sender's message is deleted at P1 and they're banned, and the fast lane still runs. A failed check fails the item, so the inbox retries it.
- Limitation: joins and join requests are handled only when the connector and workers roles run in one process (the default). Docs say so.
- Judge: the first review FAILed on two majors, both fixed here: the rejoin hook acted in shadow/paused groups, and the hooks ran on the receive loop. The minors were fixed too (errors returned, edits skipped, docs, tests). The second review FAILed on a new major: listed people skipped the group's own rejoin block, so an ask-admins instance entry let them back in. Fixed by always running the rejoin check, without an admin-re-add lift for listed people.
- Status: `passes: true`.

### Follow-ups

- Join requests come with no event from WhatsApp, so a listed requester waits up to 5 minutes plus pacing.
- Join requesters are matched by their request JID only, with no LID↔PN lookup through the LID store. In LID groups, entries whose number wasn't resolved to a LID won't match a request (they still match on join).
- `blacklistGroups.Protected` skips groups that have no settings document yet (version 0) for instance-wide adds. That's the conservative side, noted in PR #44.
