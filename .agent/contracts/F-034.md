# F-034: NFKC and invisible-character stripping

**Goal:** `normalize.Text` turns a raw text surface into a matching form (`Norm`) by applying NFKC and removing invisible characters and combining-mark floods, keeps the input as `Raw`, and reports how many obfuscation characters it removed (`Stripped`) as a signal input.

**Behaviour**
- `Raw` is the input byte-for-byte. `Norm` is valid UTF-8, is NFKC-normal, and `Text(r.Norm)` gives the same `Norm` with `Stripped == 0` (idempotent). Never panics, whatever the input.
- NFKC: fullwidth, math alphanumerics (𝐟𝐫𝐞𝐞), circled letters and ligatures fold to their plain form. Decomposed and precomposed accents give the same `Norm`. Invisibles that sit between a letter and its accent don't stop composition (`e`+ZWSP+U+0301 gives the same `Norm` as `é`).
- Removed from `Norm`, always: U+200B–U+200F, U+2060–U+2064, U+FEFF, U+202A–U+202E, U+2066–U+2069, U+E0000–U+E007F, U+FE00–U+FE0F, U+E0100–U+E01EF, U+00AD. Other default-ignorable code points may also be removed. Visible characters, spaces and newlines must not be.
- Combining-mark flood: after NFKC, a run of **4 or more** combining marks (Mn/Me) on one base is removed entirely. Runs of 1–3 stay. Invisibles inside a run don't split it.
- `Stripped` counts the input characters removed (every invisible plus every flood mark; never characters the normalizer inserted itself). **Not counted**, though still removed from `Norm`, are these legitimate uses, judged on the input as written: U+FE0E/U+FE0F right after an "emoji-like" character (anything except a letter, digit, mark, whitespace or a removed invisible), or after a digit, `#` or `*` when U+20E3 follows (keycap); U+200D between two emoji-like characters, skipping variation selectors; U+200C/U+200D between two Arabic-script letters (Persian ZWNJ); a well-formed emoji tag sequence (U+1F3F4, tags U+E0020–U+E007E, then U+E007F). Invisibles between Latin letters or digits, and unterminated tag runs, are always counted.
- Ordinary text gives `Stripped == 0`: plain English, Arabic with tashkeel, Persian with ZWNJ, accented Latin, Vietnamese, Devanagari, emoji (❤️, 👍🏽, 👨‍👩‍👧, 1️⃣, 🏴󠁧󠁢󠁳󠁣󠁴󠁿).
- Linear time: 256Ki-rune hostile input (all marks, ZWSP between letters, tag runs) finishes in under 3 s even with `-race`. Go's NFKC inserts U+034F every 30 marks; those must not be counted or left behind.

**Public surface:** package `internal/normalize`: `func Text(raw string) Result`; `type Result struct { Raw, Norm string; Stripped int }`. Later features (F-035–F-038) add fields to `Result` (variants, phones, emoji tokens) and must not change the meaning of these three. Tests read fields only and never use unkeyed literals. The stub `internal/normalize/normalize_stub.go` declares these names; replace it with the real implementation.

**Out of scope:** confusables (F-035), leetspeak, separator collapsing, repeat squeeze and emoji tokens (F-036), Arabic/Persian folding, including tashkeel removal (F-037), phone extraction (F-038), case folding, scoring weights for `Stripped`, filling in `Envelope.Texts[].Norm`.

**DESIGN.md refs:** §7.2 (steps 1–2), §5.3 (Raw/Norm), §18 testing row "Normalizers / extractors" (fuzz).

**Assumptions** (conservative, to avoid false positives)
- The emoji, Persian and tag-flag exemptions above aren't in §7.2. Without them, every ❤️ or 🏴󠁧󠁢󠁳󠁣󠁴󠁿 would raise the obfuscation signal. LRM/RLM and bidi controls have no exemption and are always counted, so the scoring feature should weigh small counts lightly.
- "Flood" means 4 or more marks, because legitimate Arabic, Hebrew and IPA text stacks up to 3.
- Later stages must not add to `Stripped`. Tashkeel removal in F-037 is folding, not obfuscation.
- The tests check `Norm` as equivalence (`Norm(obfuscated) == Norm(plain)`), plus identity only for `buy crypto now`, so F-035–F-037 can extend `Norm` without breaking them.

**Acceptance tests** (`acceptance/normalize/`)
- `TestRawPreserved`: `Raw` equals the input exactly, including invalid UTF-8.
- `TestPlainTextUnchanged`: `buy crypto now` keeps its `Norm`, with `Stripped` 0; empty input gives empty output.
- `TestNFKCFolding`: fullwidth, math bold, circled, ligature, fullwidth digits and decomposed accents each match the plain form, with `Stripped` 0.
- `TestInvisiblesStrippedAndCounted`: each listed code point inserted into `crypto` is removed and counted.
- `TestInvisibleBetweenBaseAndMarkStillComposes`: an invisible between a letter and its accent doesn't stop composition.
- `TestExemptionsDoNotCoverObfuscation`: VS16, ZWJ and ZWNJ between Latin letters or digits, and unterminated tag runs, are counted.
- `TestOnlyInvisibles`: input made only of invisibles gives an empty `Norm` with the full count.
- `TestTagSmugglingCounted`: hidden tag-character text is removed and counted.
- `TestZalgoFloodStripped`: 4+ marks per letter are removed and counted; 3 are kept and not counted.
- `TestLegitimateTextNotCounted`: the ordinary-text list above gives `Stripped` 0, with no listed invisibles left in `Norm`.
- `TestIdempotent`: normalizing `Norm` again changes nothing and strips nothing.
- `TestLargeHostileInputLinear`: 256Ki-rune floods finish within the time bound.
- `FuzzText`: no panic; valid UTF-8; NFKC-normal; idempotent; no listed invisibles; 0 ≤ `Stripped` ≤ input rune count.
