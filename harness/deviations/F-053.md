# F-053 deviations (detections table)

- §14 lists `person_id` as a person reference. app.persons doesn't exist yet (wp-f's identity PR has no migrations), so `detections.person_id` and `group_bans.person_id`/`decider_person` are plain bigints for now; a later migration adds `REFERENCES app.persons(id)` once the persons table lands (wp-f's merge re-points rows through those foreign keys).
- The `signals` jsonb holds `{signals, violations, reason}`: the violated content-rule keys (not their details, which can quote a file name or link host from the message) and the decision's explanation sit next to the scoring signals, since §14 has no separate column for them. `action_plan` stores `[{kind, priority, review: {kind, propose_ban, timeout, on_timeout, batch}}]`.
- Recording is the pipeline's job (wp-l, F-088): `Outcome.Record(ref)` builds the row and `PolicyStore.InsertDetection` stores it. Clean messages and paused groups record nothing.
