# Contract F-064 (covers F-064..F-075): the outbound action queue (WP-H)

**Goal:** every WhatsApp write goes through one persistent, deduplicated queue per bot, executed strictly serially by one executor that paces writes under a fixed ceiling, slows down on warning signs, and never posts in silent protected groups.

**Behaviour** (defaults from `DefaultConfig`)
- *Enqueue:* NotBefore defaults to now, Deadline to `DefaultDeadline`. Errors wrap `ErrInvalid` (no dedupe key, unknown kind, bad priority, kick/reject without JIDs or to a non-group, revoke without target ID and sender); nothing is stored. A dedupe key is unique across all statuses forever: a repeat returns `Inserted=false` and the first ID. A deadline already passed: not stored, `Dropped` non-empty, no error. `Cancel(key)` moves a pending action to cancelled (never executed) and reports false for running/final/unknown keys.
- *Executor:* one per bot (a second `Run` for the bot on the store returns `ErrExecutorRunning`; after the first stops, another may run). Strictly serial: never two WhatsApp calls in flight. On start, actions left `running` go back to pending and run (at-least-once). `Run` returns nil after ctx is cancelled. `State`, `Wake`, `Warn`, `Read`, `OpenBreaker` are safe concurrently with `Run`. `NewExecutor` rejects an invalid Config and nil `Groups`.
- *Pacing:* token bucket (capacity Burst=10, refill at the current rate, starts full). In ANY interval [a,b], writes ≤ Burst + rate·(b−a). After every write a pause of Spacing (1 s) + uniform 0–Jitter (1.5 s); with budget and work, the next write starts at the end of that pause (≤ 100 ms later). Per chat ≤ GroupPerMin (10) writes in any 60 s. `Read` has its own bucket (ReadBurst, ReadsPerMin) and never consumes write budget.
- *Ordering:* priority (P0 first); within a priority, deadline within UrgentWithin (1 h) first (earliest deadline first); otherwise round robin across chats (a raided group can't starve another group's single delete); within a chat revokes newest MessageTime first. NotBefore is honoured. Past-deadline actions are never executed (status expired).
- *Kicks/reject_join:* wait KickWindow (2.5 s) from CreatedAt, then all pending ones of that group and kind merge into ceil(unique JIDs/MaxKickBatch=8) calls, no duplicate JID, never a JID that wasn't enqueued, no cross-group mixing; each call is a paced write. Each action's `Result.Participants` has one outcome per own JID; a JID not in the group still ends `done`.
- *Errors:* `wa.ErrTimeout` and unclassified errors retry with full-jitter backoff 0–min(2^n·2 s, 5 min), at most MaxAttempts (6) calls, then failed. `wa.ErrRateLimited`: no WhatsApp call for RateLimitPause (60 s), `State().PausedUntil` set, then rate quartered; the action is retried. `wa.ErrNotAdmin`: failed at once, `Groups.NotAdmin(bot, chat)`, the chat's other pending admin-only actions failed without a call. `wa.ErrNotFound` on revoke: failed at once.
- *Slow-down:* warning signs (429, unclassified error, call slower than SlowAck 10 s, `Warn(WarnDisconnect)` within DisconnectWindow of a write) set rate = max(2, rate/4). Recovery +1/min per RecoverEvery (15 min) calm, never above the ceiling; `State().Rate` starts at, and never exceeds, `State().Ceiling`. `Operator.SetCeiling` is audited, applies within PollInterval, a raise doesn't make the rate jump (≤ +1 per RecoverEvery), a cut caps the rate at once.
- *Breaker:* opens on `wa.ErrTemporaryBan` / `*wa.TemporaryBanError`, `OpenBreaker`, or 3 warning signs within 10 min; alerts `AlertBreakerOpen`; only P0 actions of BreakerAllows kinds run, the rest stay pending; `Read` returns `ErrBreakerOpen`; stays open until `Operator.CloseBreaker`. Kill switch: `Operator.Pause` stops all calls on all bots within PollInterval, `Read` returns `ErrPaused`, until `Resume`; both audited.
- *Daily:* once a bot passes DailyAlert writes in a UTC day, exactly one `AlertDailyWrites` that day; nothing slows down.
- *Sends:* text is Payload.Text or a Variant, never the same text twice in a row to different chats; a send whose only text equals the previous send to another chat waits for a different text, or expires. `Result.SentText` is the text sent.
- *Silent (F-075):* a post (Kind.Posts) to a chat where `Groups.Posting` says Protected&&Silent, or errors, is refused (status refused), never calling WhatsApp, at any priority. Protected&&!Silent: ≤ 1 post per group per 60 s. Others: normal pacing. Revokes in silent groups still run.

**Public surface:** `internal/actions` as already declared (Action, Payload, Result, Priority, Kind*, Purpose*, Status*, EnqueueResult, Err*, DefaultDeadline, RevokeKey, KickKey, RejectJoinKey, Store, MemStore/NewMemStore/All, Control, GlobalScope, Config/DefaultConfig, Deps, Groups, Posting, Alerter, Alert, AlertKind*, Auditor, AuditEntry, Warn*, Executor/NewExecutor/Run/Wake/Read/Warn/OpenBreaker/State, State, Operator). `internal/wa`, `internal/wa/fake`, `internal/clock`.

**Out of scope:** the Postgres store, migration and transactional enqueue with the detection (F-064's "same transaction"), and SKIP LOCKED semantics: separate `integration` acceptance tests once the store foundation lands. OTP/review P3 sub-budgets (F-070) beyond not being contradicted, `max_bans_per_hour`, lockdown escalation, wiring to the real alerts/group-state modules.

**Assumptions:** an action that runs into ErrTimeout is not a warning sign; a not-admin failure does not raise an alert (only `Groups.NotAdmin`); "passes DailyAlert" means strictly more than DailyAlert writes; after a raise with no warnings ever, one recovery step may happen immediately.

**Acceptance tests** (`acceptance/actions`)
- TestEnqueueAppliesDefaults: NotBefore/Deadline/status defaults per kind.
- TestEnqueueRejectsInvalid: each invalid action wraps ErrInvalid and isn't stored.
- TestEnqueueDropsPastDeadline: expired-at-enqueue actions aren't stored.
- TestDedupeAcrossAllStatuses: a repeated key is a no-op whatever the first one's status, and runs once.
- TestCancelPendingRevoke: a sender's revoke cancels the pending delete; it never reaches WhatsApp.
- TestNewExecutorRejectsBadSetup / TestOneExecutorPerBot / TestExecutorIsStrictlySerial / TestCrashRecoveryRerunsRunningActions.
- TestCeilingNeverExceeded: seeded waves of 300 actions; sliding-window ceiling, spacing and per-chat cap hold.
- TestBurstSpacingAndJitter: a wave's first 10 writes go out 1–2.5 s apart with varied gaps.
- TestPerGroupCap / TestRoundRobinFairness / TestReadsUseSeparateBudget / TestNotBeforeHonoured.
- TestPriorityOrder / TestUrgentDeadlinesFirst / TestDeletesNewestFirstInGroup / TestExpiredActionsNeverRun.
- TestKicksCoalesce (table, kicks and rejections) / TestKicksWithinWindowMerge.
- TestTransientErrorBackoff / TestTransientErrorGivesUp / TestRateLimitPausesThenSlowsDown / TestPermanentErrorsFailFast.
- TestSlowDownOnWarningSigns (table) / TestRecoveryIsSlowAndCapped / TestSetCeiling / TestDailyWritesAlert.
- TestBreakerOpens (table: temp ban, ban details, OpenBreaker, 3 warnings) / TestKillSwitch.
- TestSilentGroupRefusesEveryPost / TestNonSilentGroupOnePostPerMinute / TestSendVariants.
