# F-059/F-060/F-061 deviations (decision routing)

- §8.7 `compromised.admins: delete_known_spam`: not honoured. The contract's conservative reading is that the admin exemption (§8.6 "never act on admins") wins; a possibly hacked admin only produces an `alert` review. The key exists and validates so the setting can be wired later.
- §8.3 (b) ask_before_action: applied to content-rule violations too (nothing is deleted until an admin decides), per the contract's reading of "nothing is deleted or banned until an admin decides". For a still-uncertain message the ask_before fallback is `leave`, never a delete.
- §9.3 "if a message is both, the spam route applies": followed literally, including when the matrix cell is `allow` (the message is then left alone even if it also breaks a content rule).
- A spam message whose content type has no matrix row goes to admins (`ask`).
- Review timeouts: `review.on_timeout: auto_ban` is honoured only for known (CERTAIN) spam from a new/unknown sender in `auto` mode; for AI-verified spam (early-AI safety, §9.2), established or hacked members and ask modes it is replaced by `keep_deleted_no_ban`.
- `policy.action: ban` and `policy.repeat → ban` never ban an established or possibly hacked member or in ask modes; admins decide instead.
- Identity priors: a finding resting only on priors (positive-weight signals all priors) that is not known or AI-verified spam gets no action and no review; known or AI-verified spam is acted on as spam (its evidence isn't a prior).
- Band and Source are policy-local string types with the same values as `scoring.Band`/`scoring.Source` (wp-e), so the decision engine builds and tests before wp-e lands; an adapter from `scoring.Verdict` comes with the integration.
- §8.7 with `compromised.enabled: false`: a member still flagged possibly compromised (an open event from another group or from before the switch) is never auto-banned; their spam is deleted and admins get a `ban_decision` review instead of the `hacked` review.
