# F-110 · AI result cache and one call per cluster

## 2026-10-17

Built in the WP-J bundle (log: `harness/progress/F-106.md`):
- `internal/ai/cache`: the key is sha256 over the normalized text, context hash, model and prompt version, kept for 30 days. Copies in the same SimHash cluster or campaign reuse the first verdict through a single shared call, so 40 groups cost one call. Only spam and not_spam verdicts are kept. Every caller except the one that made the call gets the sanitized copy.
- `internal/ai/aistore.Cache` (PR 3): the Postgres store on `app.ai_cache`, plus a River periodic purge (`RegisterPurge`, every 6 h).
- `gateway.Sanitize` redacts and caps the stored reason, and drops it for not_spam.

Deferred to the wiring (wp-l, the main binary):
- build `gateway.NewResultCache(aistore.NewCache(pool), clk)`;
- register the purge job;
- pass the SimHash cluster or campaign ID (wp-g) in `Item.Cluster`;
- call `aicontext.Buffer.Remove` on delete-for-everyone events.

## Follow-ups
- A cluster's shared call uses the budget of the group that started it.
- Reusing a not_spam verdict across a cluster for 24 h could let a spammer seed a cluster with a harmless variant; consider exact-key reuse only for not_spam (plan change).
