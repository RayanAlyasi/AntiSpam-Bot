## 2026-10-17 · fix · stable order for texts read by reflection

- The reflection walk (`internal/wa/adapter/build_reflect.go`) used `protoreflect.Message.Range`, which protobuf-go deliberately randomizes per binary (the seed is a hash of the executable), and `Map.Range`, which has no order. So texts of interactive, commerce and unknown messages came out in a different order between builds: `TestChannelsInvitesPollsLocationsEventsCommerce/buttons` failed in one worktree and passed in others. The walk now goes by descriptor field index (declaration order) and sorts map keys, so normalization, SimHash/MinHash and AI cache keys are the same across builds and restarts.
- Pinned by `TestReflectedTextsFollowDeclarationOrder` (fields set out of declaration order). Checked against several build variants: the old code failed under one, the new code passes all.
- Audit: no other code under `internal/` iterates `Range` or maps into a hash or fingerprint input. Nothing is deployed, so no stored fingerprints need rebuilding.
