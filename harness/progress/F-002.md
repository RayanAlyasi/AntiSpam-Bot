## 2026-10-17 · F-002 · foundation bundle (F-001–F-008, F-099), one PR

Built on the fast track the user asked for (2026-10-17): work package C ships as one PR with one
judge review. F-002 kept its architect contract (`.agent/contracts/F-002.md`) and hidden
acceptance tests; the other features have builder-written tests only.

- **F-002 config:** `internal/config` loads the defaults, an optional `config.yaml`
  (`CONFIG_FILE`, else `./config.yaml`) and the environment (env wins), and validates the result
  strictly. Keys: pacing, presets, scoring, AI. Also `config.example.yaml` and
  `docs/CONFIGURATION.md`. `LOG_LEVEL` takes `module=level` entries (for F-001). `HTTP_ADDR` (for F-007/F-008).
- **F-001 logging:** `internal/logging`: zerolog JSON, a level per module (`For(module)`), request
  and detection IDs on loggers and contexts, and `MaskPhone`/`MaskJID` plus `Phone`/`JID` types
  that mask when logged.
- **F-003 Postgres:** `store.Open` (pgx v5 pool, session TimeZone UTC, timestamptz scanned as UTC),
  `store.InTx` (rolls back on error or panic), and `internal/store/storetest` (one testcontainers
  Postgres per test binary, a fresh database per test cloned from a migrated template).
- **F-004 migrations:** the `migrations` package embeds the goose SQL files; `store.Migrate` runs
  them on start under a Postgres advisory lock. Schemas `app` and `whatsmeow`; `sqlc.yaml`
  generates into `internal/store/db` (sqlc diff is green).
- **F-005 River:** goose migration 2 runs River's own migrations to River schema version 8 in
  schema `app`. `internal/store/jobs` wraps the River client: workers only with `Work`, `InsertTx`
  for transactional enqueue, and a periodic heartbeat job.
- **F-006 audit log:** `app.audit_log` (migration 3), `store.WriteAudit` (works on a transaction)
  and `store.ListAudit` (per group, newest first, paged by ID).
- **F-007 health:** `api.OpsHandler` serves `/metrics`, `/healthz` and `/readyz` (DB ping plus at
  least one connected bot).
- **F-008 roles:** `cmd/antispam` runs connector, workers and api (or a `-roles` subset), stops them
  on SIGTERM/SIGINT within `-shutdown-timeout` (8s), and exits 1 if a role fails or shutdown overruns.
  `-check-config` validates the config and exits. `docs/RUNNING.md` documents it.
- **F-099 newer schema:** `store.Migrate` returns `*SchemaTooNewError` (database version, binary
  version and what to run) before applying anything, and the binary exits 1.
