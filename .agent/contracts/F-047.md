# F-047: URL canonicalization, eTLD+1 and WhatsApp-native targets

> Acceptance tests were waived by the user's fast-track decision for v0.1 work package A (this feature isn't core). The builder's table, property and fuzz tests carry the proof, and the judge checks them against this contract.

**Goal:** turn an extracted URL into one canonical form for matching and dedup, give it its registrable domain, and recognize WhatsApp group-invite, channel and chat links as their own targets.

**Behaviour**
- `Canonicalize(raw)` accepts an `http`/`https` URL (F-046 output). For anything without a host, with another scheme, or with an invalid IDN host, it returns an error. The caller keeps the raw string as evidence.
- Canonical form:
  - lower-case scheme and host;
  - trailing dot removed from the host;
  - host in ASCII (punycode, via `golang.org/x/net/idna`);
  - default port removed (`:80`/`:443`);
  - empty path becomes `/`;
  - fragment dropped.
  
  **Path and query case is kept** (invite codes and channel IDs are case-sensitive). So `HTTP://EXAMPLE.COM:80`, `http://example.com.` and `http://example.com/#x` share a `Canonical`, and `http://пример.рф/` and `http://xn--e1afmkfd.xn--p1ai/` share a `Canonical` and a `Host`. `UnicodeHost` gives `пример.рф` for both.
- Tracking parameters are removed, matching names case-insensitively: at least `utm_*`, `fbclid`, `gclid`, `dclid`, `gbraid`, `wbraid`, `msclkid`, `igshid`, `mc_cid`, `mc_eid`, `yclid` and `_ga`. The remaining parameters keep their order and values (`wa.me/…?text=…` keeps `text`). An empty query leaves no `?`.
- `Domain` is the eTLD+1 from `golang.org/x/net/publicsuffix` **including private suffixes**:
  - `a.b.example.co.uk` gives `example.co.uk`;
  - `evil.github.io` and `x.blogspot.com` stay as they are, so blocking one user never blocks the platform;
  - IP hosts and hosts that are themselves a suffix (`co.uk`) give an empty `Domain`.
- WhatsApp-native targets are set only when the canonical host is exactly one of these. Look-alikes (`chat.whatsapp.com.evil.xyz`, `chat-whatsapp.com`, `wa.me.example.com`) get no target.

  | Host and path | Kind | ID |
  |---|---|---|
  | `chat.whatsapp.com/<code>` or `/invite/<code>` | `TargetGroupInvite` | the code |
  | `(www.)whatsapp.com/channel/<id>` | `TargetChannel` | the ID |
  | `wa.me/<digits>` or `api.whatsapp.com/send?phone=<digits>` | `TargetPhone` | E.164 via `normalize.ParsePhone("+"+digits, "")`; no target if the number is invalid |
  | `wa.me/message/<code>` | `TargetMessage` | the code |
  | `wa.me/qr/<code>` | `TargetQR` | the code |

  A native host with no code (`wa.me/`, `chat.whatsapp.com/`) gets no target.
- Idempotent: `Canonicalize(u.Canonical)` returns the same `URL`. Never panics.

**Public surface:** package `internal/normalize/urls`:
- `func Canonicalize(raw string) (URL, error)`;
- `type URL struct { Canonical, Host, UnicodeHost, Domain string; Target *Target }`;
- `type Target struct { Kind TargetKind; ID string }`;
- `type TargetKind string` with the constants `TargetGroupInvite`, `TargetChannel`, `TargetPhone`, `TargetMessage` and `TargetQR`.

**Out of scope:** resolving targets (`GetGroupInfoFromLink`, newsletter info), shortener expansion, allow/deny lists, reputation, look-alike detection, path normalization beyond the above (dot segments, percent-encoding case).

**DESIGN.md refs:** §6 URL analyzer steps 2–3, §7.5 ("Links" saved per corpus entry).

**Assumptions**
- Private suffixes are included in `Domain` (see above), so blocking one user's subdomain never blocks a shared platform.
- The scheme is kept, not unified. `http` and `https` versions are distinct canonical URLs but share `Domain` and `Target`, which is what the lists match on.

**Proof (builder tests):** table tests per canonical rule, tracking parameter, eTLD+1 case (ICANN, private, IP, bare suffix), each target kind, and each look-alike non-case; fuzz (no panic; for every success, idempotent and `Host` is lower-case ASCII).
