# Contract: AI gateway bundle (WP-J: F-106, F-107, F-108, F-109, F-110, F-111, F-112)

**Goal:** Turn the provider-neutral AI classifier into a working, bounded T3 tier: two adapters
(Anthropic, OpenAI-compatible), a redacted context bundle, budgets and metrics, a result cache with
one call per cluster, and the routing of the UNCERTAIN band, with AI evidence never auto-banning.

**DESIGN.md refs:** §7.0, §7.3 (confidence source), §7.4, §8.3, §9.2 (early-AI safety, track
record), §11 (AI results row), §14 (`ai_cache`, `ai_usage`), §16 (AI metrics, AI budget alert),
§17 (AI data), §18 (scoring/decision properties).

**Tests:** F-106 to F-110 are verified by builder-written table, property and fuzz tests next to
the code (recorded `httptest` fakes for the adapters; Postgres stores under build tag
`integration` with testcontainers). Hidden acceptance tests cover the core features F-111 and F-112
only; they are written in a second pass once the pipeline (F-088), the auto-ban matrix (F-058) and
the AIClassifier/band types (F-103 to F-105) exist.

## Shared surface: `internal/ai/llm`
`Completer{Complete(ctx, Request) (Response, error); Caps() Caps}`; `Request{System, Data, Schema,
Mode (ModeNative|ModeJSON), MaxTokens}`; `Response{Text, Model, Usage{InputTokens, OutputTokens,
CacheReadTokens, CacheWriteTokens}}`; sentinels `ErrTimeout`, `ErrRateLimited`, `ErrUnavailable`,
`ErrAuth`, `ErrInvalidRequest`, `ErrRefused`, always wrapped with `%w` so `errors.Is` works.
No provider type leaves an adapter package (AI-001). Errors and logs never contain the API key.

## F-106 Anthropic adapter: `internal/ai/anthropic`
`New(Options) (*Client, error)`, `Options{BaseURL, APIKey, Model, Timeout, MaxTokens}`; `*Client`
implements `llm.Completer`.
- Uses the official anthropic-sdk-go. `System` goes out as a system block marked
  `cache_control: ephemeral`; `Data` is the single user message. ModeNative sends the schema as
  native structured output. Usage maps input, output, cache-read and cache-write tokens.
- Key, URL and model come only from `Options`. Setting `ANTHROPIC_API_KEY`/`ANTHROPIC_BASE_URL` in
  the environment changes nothing. An empty key or model makes `New` fail.
- No SDK retries: one `Complete` sends exactly one HTTP request. Retry policy belongs to the layer
  above.
- Mapping: deadline or `Timeout` exceeded → `ErrTimeout`; 429 → `ErrRateLimited`; 5xx/529 or
  connection failure → `ErrUnavailable`; 401/403 → `ErrAuth`; other 4xx → `ErrInvalidRequest`; a
  refusal stop reason → `ErrRefused`. Zero `Timeout` means 5 s.
- An `ai.AIClassifier` built on this adapter (with F-103/F-104/F-105) returns **unsure** on every
  one of these errors. Nothing is deleted on failure (§7.4 Guardrails).

## F-107 OpenAI-compatible adapter: `internal/ai/openaicompat`
Same shape: `New(Options)`, where Options adds `StructuredOutput` (`auto`|`native`|`json`).
- POSTs `{BaseURL}/chat/completions`. ModeNative sends `response_format` `json_schema` (strict).
  ModeJSON sends `json_object` and never sends a schema. The `Authorization` header is sent only
  when `APIKey` is non-empty, because local servers (Ollama, llama.cpp, vLLM, LM Studio) need no
  key.
- `auto`: the first call tries native. If the server rejects `json_schema` with 400/422, that call
  is sent once more in JSON mode, and every later call in the process uses JSON mode. The switch
  is safe under concurrent calls and shows in `Caps().NativeSchema`. 401/403/404/429/5xx never
  trigger the fallback. `native` never falls back. `json` never sends a schema.
- Missing `usage` → zero usage. Missing `model` → the configured model. Error mapping as in F-106,
  including a `refusal` field → `ErrRefused`. Timeouts and errors end as unsure.

## F-108 Context bundle
- Built only when the group's `ai.context` is on (default on). When it is off, no context is
  sent and the context hash is the constant "no context" value.
- Read-only from the 72 h inbox. Nothing new is stored, ever (§17).
- Contents: the replied-to message, including a quoted status, and whether it was flagged; up to
  N (default 5) earlier messages in the same chat within 10 minutes before the judged message,
  each truncated to 200 characters; the group's name, topic and allowed-content summary; sender
  context (tenure bucket new/weeks/months/years, role, recent message count, just-joined, and for
  edits the original text); replies that already exist.
- Redacted with the shared helper (F-101): phone numbers, emails and names other than the judged
  message's own content are masked. The sender's phone number and name are never included.
- The context part is at most 2,000 characters. The oldest context items are dropped first; the
  judged message is never dropped. Lengths count runes, and truncation always yields valid UTF-8.
- Fenced and labelled as data, not instructions. Message text containing the fence delimiter or
  fake labels cannot close the fence or forge a section (fuzz-tested).
- Deterministic: the same inputs give the same bundle bytes and the same context hash.

## F-109 Budgets and metrics
- Limits: calls per group per day (`detection.ai.daily_budget_calls`, default 200), per instance
  per day and per instance per month. `Allow` runs before a call and `Record` after it, with
  tokens and cost. `Allow` is atomic: concurrent callers never exceed a limit (property test).
- A denied `Allow` means: no provider call; the item goes to admins; nothing is deleted.
- One operator alert per budget per window when 80% is reached. Repeated calls, restarts or
  concurrent callers in the same window raise no second alert.
- `ai_usage(day, group_jid, calls, input_tokens, output_tokens, cost_micros)` sits behind a
  store interface; domain code never imports pgx (GO-005). Time comes from the injected clock.
- Prometheus: calls (by provider/model/outcome), the message counter or ratio for calls per 1,000
  messages, tokens, cost, a latency histogram, cache and cluster-reuse hits, invalid-output
  retries, unsure verdicts, budget remaining.

## F-110 Result cache and one call per cluster
- Key = sha256(normalized text + context hash + model + prompt version). Entries last 30 days in
  `ai_cache` behind a store interface. Changing the model or the prompt version misses the cache.
- A copy in the same SimHash cluster or campaign (ID supplied by the caller) reuses the first
  verdict, across groups too. 40 copies in 40 groups cost one provider call, and that holds under
  concurrency (single-flight). A reused or cached verdict is marked as such for the explanation
  and metrics.
- Only definitive verdicts (spam / not_spam) are cached or reused. Unsure, invalid output,
  timeouts and errors are not. Cache and reuse hits count against no budget.

## F-111 T3 verification of the UNCERTAIN band (outcome level)
- Only the UNCERTAIN band (score ≥ `T_review` and not CERTAIN) reaches the AI. CERTAIN and clean
  messages never call it.
- AI spam with confidence ≥ `ai.spam_confidence` (default 0.90, inclusive): the message is
  deleted through the action queue, the verdict records source `ai`, and the ban goes to admins as
  a review. In `ask_before_action` mode nothing is deleted until an admin decides.
- AI not_spam with confidence ≥ `ai.not_spam_confidence` (default 0.90): no action and no review.
  The verdict is logged.
- Still uncertain (unsure, either label below its threshold, invalid output after one retry,
  timeout, error, budget exhausted, AI not configured, AI disabled for the group): the item goes
  to admins and nothing is deleted (unless `uncertain.delete_while_pending` is true).
- Idempotent: a redelivered message makes no second provider call, delete or review.
- Exact Go surface is to be fixed in the second pass, against F-088.

## F-112 Early-AI safety (outcome level)
- A ban whose strongest evidence source is `ai` routes to ask admins in every preset, mode,
  content type and sender standing while the instance track record is unmet. The track record is
  an injected interface that defaults to unmet; v0.1 never meets it (tracking lands in v0.4).
- A near-duplicate match below the tight CERTAIN thresholds (source `rules`) never deletes or bans
  on its own; it only feeds the AI.
- Even with the track record met, `ai` bans automatically only where the matrix cell explicitly
  lists `ai`. It is never enabled automatically.
- Source `known` evidence follows the matrix unchanged. Exact Go surface is fixed in the second
  pass, against F-058.

## Out of scope
Vision (T4), the Google adapter, batch mode, track-record tracking (v0.4), few-shot selection,
the prompt text and the verdict parser (F-103 to F-105), the `.autoban` command and website
greying, shadow-mode plumbing, review message formatting.

## Assumptions (conservative readings)
1. §11 omits the context hash from the AI cache key, but §7.4 includes it. The key includes it,
   so a verdict is never reused across different context.
2. Only definitive verdicts are cached or reused. Unsure and errors are always retried later.
3. `ai_cache.result` never holds message text: the reason is redacted and capped at 200
   characters, and dropped entirely for not_spam (§17: no normal-message text outside the inbox).
4. Budget windows are UTC calendar days and months. Each provider request (including the
   invalid-output retry) is recorded. Cache and reuse hits are free. Each budget scope alerts once
   per window.
5. Zero timeout means 5 s for both adapters. Local deployers raise it in config. A short timeout
   only produces more admin reviews, never deletions.
6. Admin and allow-listed senders never reach the AI: their messages are untouched (§8.3).
7. The threshold comparison is inclusive (≥ 0.90), as written in §7.0.

## Planned acceptance tests (F-111, F-112; second pass, `acceptance/ai/`)
- `TestAISpamDeletesMessageAndAsksAdminsForBan`: spam ≥ 0.90 → delete queued, ban review, no kick.
- `TestAISpamConfidenceBoundary`: 0.90 → delete; 0.89 → ask admins, nothing deleted.
- `TestCertainAndCleanMessagesNeverCallAI`: fake classifier sees zero calls for CERTAIN and below `T_review`.
- `TestStillUncertainAsksAdminsNothingDeleted`: table of unsure, low confidence, timeout, error, invalid output, budget exhausted, AI not configured, AI disabled.
- `TestAINotSpamHighConfidenceLoggedOnly`: no delete, no review, no ban.
- `TestAskBeforeActionModeKeepsAISpamVisible`: mode (b) → review only, message stays.
- `TestRedeliveredMessageClassifiedOnce`: one AI call, one delete, one review.
- `TestPropertyAISourceNeverAutoBansWithoutTrackRecord`: every preset × type × mode × standing.
- `TestPropertyLooserNearDuplicateNeverActsAlone`: source `rules` alone → never delete or ban.
- `TestAIAutoBanOnlyWithTrackRecordAndExplicitCell`: met but cell lacks `ai` → ask.
- `TestKnownEvidenceStillAutoBans`: a control so the properties above aren't vacuous.
