# F-002: Optional config.yaml with safe defaults and env overrides

**Goal:** `config.Load` merges built-in defaults, an optional `config.yaml` and the documented
environment variables (env wins), validates the result, and the bot still starts with no file.

**Behaviour**
- File: `CONFIG_FILE` names it; unset means `config.yaml` in the working directory. A missing
  default file means defaults. A missing explicit `CONFIG_FILE` is an error naming the path.
- Empty, comment-only, UTF-8-BOM and CRLF files load. Keys left out (or an empty section like
  `pacing:`) keep their defaults; a partial file never zeroes the other keys.
- Keys (YAML, snake_case; operator-facing API, §23.7) and defaults:
  `pacing.` `ceiling_per_min` 20, `burst` 10, `spacing_base` 1s, `spacing_jitter` 1.5s,
  `group_ceiling_per_min` 10, `slowdown_factor` 0.25, `min_rate_per_min` 2,
  `recovery_step_per_min` 1, `recovery_interval` 15m, `max_kick_batch` 8, `daily_alert_writes` 7500;
  `presets.default` standard (relaxed|standard|strict|ask_admins);
  `scoring.thresholds.` `review` 0.60, `delete` 0.85, `ban` 0.95; `scoring.weights` {} (signal → log-odds);
  `ai.` `provider` "" (off; anthropic|openai_compatible|google), `base_url` "", `model` "",
  `api_key_env` AI_API_KEY, `timeout` 5s, `structured_output` auto (auto|native|json), `spam_confidence` 0.90.
- Env overrides (only the variables §19.1 names): `AI_PROVIDER`, `AI_BASE_URL`, `AI_MODEL`,
  `AI_TIMEOUT` override `ai.*`. The API key is read from the env var named by `ai.api_key_env`
  (never from the file). Empty or blank env values don't override. `DATABASE_URL`, `PUBLIC_URL`,
  `OPERATOR_PHONES`, `LOG_LEVEL` keep their F-000 behaviour.
- `AI.Enabled()` is true only when a provider is set. With a provider: `model` is required;
  `openai_compatible` needs `base_url`; `anthropic`/`google` need the API key. AI_MODEL alone keeps AI off.
- Errors (bot refuses to start): unknown keys (typos; also `ai.api_key`, so secrets stay out of
  the file), wrong types, bad YAML, unknown enum values, non-positive counts, rates or durations (`spacing_jitter` may be 0), `presets.default: custom`,
  `min_rate_per_min` > `ceiling_per_min`, `slowdown_factor` outside (0,1), thresholds outside (0,1]
  or not `review < delete <= ban`, `spam_confidence` outside (0,1], non-finite weights, `base_url`
  not http(s) with a host. Validation errors name the dotted key or env var. No error or warning
  ever contains the API key value.
- `Warnings`: raising `pacing.ceiling_per_min` or `pacing.burst` above the default adds a warning
  naming the key (risky, §10.3). Defaults and lower values add none.
- Idempotent: loading twice gives equal results; one load never leaks into the next.
- `config.example.yaml` at the repo root lists every key above with a comment and its default,
  and loads to exactly the defaults.

**Public surface** (`internal/config`): `Config{…existing…, Pacing Pacing, Presets Presets,
Scoring Scoring, AI AI, Warnings []string}`; `Pacing{CeilingPerMin, Burst int; SpacingBase,
SpacingJitter time.Duration; GroupCeilingPerMin int; SlowdownFactor float64; MinRatePerMin,
RecoveryStepPerMin int; RecoveryInterval time.Duration; MaxKickBatch, DailyAlertWrites int}`;
`Presets{Default string}`; `Scoring{Thresholds Thresholds; Weights map[string]float64}`;
`Thresholds{Review, Delete, Ban float64}`; `AI{Provider, BaseURL, Model, APIKeyEnv, APIKey string;
Timeout time.Duration; StructuredOutput string; SpamConfidence float64}`; `func (AI) Enabled() bool`;
`func Defaults() Config`; `func Load(getenv func(string) string) (Config, error)`.
YAML library: `go.yaml.in/yaml/v3` (strict decoding via `KnownFields`).
`config_stub.go` declares the new types; the five `Config` fields still have to be added in
`config.go`, so the acceptance package won't compile until they exist (`Config.Pacing undefined`).

**Out of scope:** vision settings, AI budgets, rule-pack/feed subscriptions, languages, retention
overrides, `SESSION_SECRET`, preset contents (F-055), how weights merge (F-050), env vars for
non-AI keys, logging `Warnings` at start-up (cmd/antispam, F-008), `.env.example` (F-091).

**DESIGN.md refs:** §19.1, §23.7, §10.3, §10.4, §7.3, §7.4, §12.1, §12.2.

**Assumptions** (conservative readings): `CONFIG_FILE` and the key names above are new operator API;
misconfiguration fails at start like `LOG_LEVEL`; one 5s AI timeout default for every provider;
no env var is invented for non-AI keys.

**Acceptance tests** (`acceptance/config/config_test.go`)
- TestDefaultsMatchDesign: every default equals the DESIGN value.
- TestLoadWithoutFileUsesDefaults: no file (default path absent) loads Defaults(), AI off, no warnings.
- TestLoadReadsDefaultPathInWorkingDir: `./config.yaml` is read when CONFIG_FILE is unset.
- TestExplicitConfigFileMissingIsError: a missing CONFIG_FILE path errors and names it.
- TestEveryKeyIsHonoured: each dotted key, set in a file, lands in its field.
- TestPartialFileKeepsOtherDefaults: one key or empty sections never zero the rest.
- TestEmptyCommentBOMAndCRLFFiles: all load to defaults.
- TestDesignAIExampleLoads: the §7.4 YAML example loads and enables AI.
- TestEnvOverridesFile: AI_* beat the file; blank env doesn't; env completes a partial file.
- TestAPIKeyComesFromNamedEnvVar: `ai.api_key_env` picks the variable.
- TestAIRequirements: provider-specific required settings; AI_MODEL alone stays off.
- TestInvalidConfigIsRejected: table of invalid files/env, each error naming its key.
- TestSecretsNeverInFileOrErrors: `ai.api_key` is rejected and the value is never echoed.
- TestRaisingPacingWarns / TestSafePacingDoesNotWarn: risky-raise warnings, no false positives.
- TestLoadIsIdempotentAndIsolated: repeated loads match; weights don't leak between loads.
- TestExampleFileDocumentsEveryKey: config.example.yaml has every key, commented, = defaults.
