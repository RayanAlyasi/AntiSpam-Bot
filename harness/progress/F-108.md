# F-108 · Context bundle from the 72 h inbox

## 2026-10-17

Built in the WP-J bundle (log: `harness/progress/F-106.md`): `internal/ai/aicontext`. `Build` returns wp-e's `ai.Context` with the replied-to message (and whether it was flagged), up to N = 5 previous messages from the last 10 minutes, the group's name, topic and allowed-content summary, sender context and existing replies. Every text goes through wp-a's shared redaction helper (phone numbers, emails, mentions and every sender's name masked) and is truncated to 200 runes; the whole context is capped at 2,000 runes, oldest dropped first. `ai.RenderData` JSON-encodes it inside the data fence; a fuzz test shows message text can't break out. Off when `ai.context` is off (`NoContextHash` keeps cache keys stable). The hash is deterministic, for the result-cache key.

The source is `aicontext.Buffer`: recent messages per chat in memory only (100 per chat, one hour, `Sweep` for idle chats), so nothing new is stored. `Source` lets a 72 h inbox reader stand in later.

Deferred: the pipeline feeds the buffer and calls `Build` before `Verifier.Verify` (wp-l wires it, F-088).

## Follow-ups
- A reader over wp-f's inbox (F-015) could back `Source` after a restart; the in-memory buffer starts empty, so the first minutes after a restart get less context.
